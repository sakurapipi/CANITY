# CANITY

纯 C / Win32 GDI 编写的第一人称像素恐怖逃生游戏。
射线投射、纹理采样、Z-Buffer 和后处理都由 CPU 在内存位图中完成，无需 OpenGL 或 DirectX。
默认画面、音效与背景音乐都由代码程序化生成；Windows x64 单机版可直接运行，也可以往 `music/` 放文件替换配乐。

当前版本：**v2.4-alpha「地基」· 2026-11-06**（预发布）。下载见 [Releases](https://github.com/sakurapipi/CANITY/releases/latest)，完整版本记录见 [CHANGELOG](CHANGELOG.md)。

> **v2.4 是一个版本、四个站点**：`alpha 地基 → beta 回声 → rc 厂区 → 正式`。
> 这次发的是第一站。它几乎不改玩法，改的是**数据层不可以出错的地方**。

## v2.4-alpha「地基」更新 · 2026-11-06

一句话：**让存档不再丢东西，并且让"测试通过"这句话第一次变得可复核。**

### 三条测试/工具终于入库

以前 CI 跑不了任何测试 —— `tests/test_runtime.c`（11,508 项检查）、
`tools/partition_check.py`、`tools/build_validate.py` **都不在仓库里**，
只在开发机上。所以「测试全部通过」这句话，任何人都无法验证。

- 三个文件入库；`.gitignore` 从「忽略整个 `tests/` `tools/`」改成
  「忽略目录内容 + 定向白名单」——`!tests/xxx` 对已忽略目录是无效的，
  这一点本轮实测过。
- 新增 `tools/build_sources.py`：**唯一的源文件清单**。
  CI、Release、本地构建都读它，不再各自手写目录
  （v2.3.8 就漏过一次 `src/save/`）。
- 新增 `.github/workflows/ci.yml`：每次 push / PR 编译并跑三条检查。
- **`release.yml` 改成调用同一个 `build_validate.py`** ——
  发布必须建立在测试通过之上，不再「只要编译成功就发」。

### 存档不再丢未知块

存档格式是「信封 + 块表 + 载荷」，但以前**写盘只写已知的那一块**，
读盘也只取它。于是任何新块（将来的 `SC_SETTINGS` / `SC_WORLD`）
只要被旧版本读一次再存一次就没了。

- 读档时记录**完整的有序块目录**（未知块数据独立拷贝）。
- 写盘按原顺序重建：`SC_LEGACY29` **原位替换**，未知块原样写回。
- 首次运行 / 裸档升级没有目录时，把已知块追加到末尾。
- **重复块 ID 直接拒绝改写**：不写盘、保留原文件、报明确错误。
  在处理玩家存档时静默挑一份，等于替玩家做决定。
- 两个写盘入口（`SaveSettingsOnly` / `SaveGame`）现在共用一个序列化出口，
  容量按未知块动态算 —— 原来是两份独立的固定缓冲，
  加块后必然不够，而且是「改一处漏一处」。

### 云同步不再把「长度不同」当损坏

以前用**本地**长度去要求云端，长度不等就直接判损坏。
而拆块必然改变长度 —— 所以这个耦合不修，任何拆块动作都会让云同步全线报错。

- 远端按**自己的**长度下载、校验；
- 同秒不同内容不再猜先后，而是报 **冲突**：不覆盖任何一方；
- 判定逻辑抽成纯函数 `SteamZoneCloudDecide`，**不需要 Steam 就能单测**。

### 每日奖励：加钱与落盘成对

以前是「先加钱、下一帧再存」。中间那段窗口里钱只在内存，
而领取标记也没落盘 —— 崩溃重启后可以再领一次。

现在：**加钱 → 同步写盘 → 写成功才算数**；失败就把钱退回去并提示。
代价是极端情况下玩家可能损失一次奖励，但**绝不会重复发放**。

> 明确边界：**本版本不提供「防恶意整体回滚存档」的保证。**
> 恢复整个旧存档目录仍然可以重置领取状态 —— 那是单机游戏的固有限制，
> 真正的防线需要可信的服务器账本，本项目目前没有。

### 两个小修

- **破门石不再双报噪音**：破锁已经发过 20 格冲击声，落地/撞墙/到期
  三个分支不再各叠一次 15 格。
  （实测修正：这两次调用本来就会被 `SuspicionAdd` 的「同源 2 格内合并」
  并成一个点，所以玩家之前感觉不到差别 —— 它是代码卫生与未来正确性问题，
  不是体验缺陷。等 beta 的 `SoundEvent` 把强度与类别分开后，它会真正生效。）
- **写盘错误不再被吞**：`FlushFileBuffers` / `CloseHandle` 的返回值都检查，
  保留**第一次**失败的错误码；备份失败也可见。
  对存档来说，flush 失败等同于写失败 —— 不报出去就是谎报"保存成功"。

### 测试

`11,481 → 11,508` 项运行期断言。新增的都是**真行为**，不是源码字符串检查：

| 新增 | 钉住什么 |
|---|---|
| `test_save_unknown_chunk_roundtrip` | 塞 `0x7777` → 读 → 改字段 → 存 → **未知块逐字节相同** |
| 同上 · 重复 ID 分支 | 重复块 ID 的存档必须被**拒绝**，不是静默挑一份 |
| `test_cloud_decide_length` | 长度不同 ≠ 损坏；同秒冲突不裁决；篡改被抓 |
| `test_save_backend_errors` | NULL / 空路径 / 目录不存在都必须返回非 0 |
| `test_stone_break_single_event` | 一次破锁只留一个可疑点 |
| 校验和黄金向量 | 改坏 FNV 常数立刻红（以前全绿 —— 见下） |

> **这一轮抓到的最有价值的一个问题**：
> 第一次做「注入缺陷验证 CI 会变红」时，我把 FNV-1a 的偏移基数改了一个数字，
> **整套测试仍然全绿**。因为 `seal` 和 `validate` 用的是同一个坏掉的函数，
> 两边互相满意。而现实中这会让**所有老存档被判成损坏**。
> 现在有对已知输入给出已知值的黄金向量了。

### 已知问题

- **战役第 3/5 关的出口位置可能不正确**。已定位：出口在 `game.c:1752`
  读 `breaker`，但配电箱要到 `:2278` 才真正放置 —— 读到的是**上一层的位置**，
  之后 `:1774` 又无条件覆盖一次。修它必须重排 `GenerateLevel` 的依赖顺序，

  （存在 / 取大小 / 下载）没有在真实 Steam 环境跑过 ——
  所以本版本**不承诺云存档恢复**。

## v2.3.9 更新 · 2026-11-05

存档分区、投石改造、每日任务重写，以及一批操作手感修复。

### 存档分区：`src/save/`

存档从 `src/save.c` 里切出来，成为独立分区，和 Steam 专区共用一份格式契约。

- 新增 `include/save_format.h`（容器契约）＋ `src/save/save_container.c`（打包/解包）
  ＋ `src/save/save_backend.c`（原子写、云同步）。
- 存档文件现在以 **`CSAV` 信封**开头（`SAVE_ENVELOPE_MAGIC 0x56415343`）：
  20 字节头 + 块表 + 载荷。**本地文件和云端对象是同一份字节**，
  不再需要在上传时临时包一层。
- 块表 `[id u16][schema u16][size u32]`：`SaveBlob` 整体暂时作为 `SC_LEGACY29` 一块。
  加字段 → 块内 schema +1；加系统 → 新增一块。**未知块原样保留并写回**，
  所以云端新旧版本能互通。
- 容器版本 `SAVE_CONTAINER_VERSION 1` 和载荷版本 `SAVE_VERSION 29` **各自独立**。
- 修掉三处：信封版本号写死 26、`stamp` 取文件 mtime（拷贝会重置）、
  云→本地用裸 `fopen`（绕过原子写与 `.bak` 链）。
- 分区检查加规则：**除 `save_backend.c` 外任何文件不许直接读写 `*.sav`**。

### 投石 → 破门石

投石原来只有一个弱化版噪音源，比不过诱饵、也比不过烟雾。
现在给它一件别的道具做不到的事：

- **砸在锁箱 2.5 格内 → 锁直接崩开**，跳过锁盘小游戏。
- 代价是 **20 格噪音** —— 砸完就得跑。
- 和宝箱怪的扳手解法是同一族：同一个障碍，给「动手」和「动脑」两条路。
- 顺手清掉一条整段失效的伤害管线（`SHOT_DAMAGE / RunThrowDmgMul / chargeBonus`
  算出来立刻被 `(void)base` 丢弃）。

### 每日任务重写

`src/daily.c` 保合约重写（枚举顺序、存档布局、27 个公开 API 全部不变），
重写的是内部：

- **修掉无限刷金币**：原来只判 `done`，而 `done` 从存档恢复 ——
  完成领 800 → 读一份完成之前的旧档 → `done` 顶回 0 → 再做一遍 → 无限循环。
  现在 `lastCompleted` 做第二道闸门并**单调不回退**，旧档压不回去。
- 目标从两数组 ＋ 一段 `if` 收敛成一张表（`lo/hi/round5/cumulative`），
  加目标忘补表会**编译失败**而不是运行期越界。
- 领奖不再在 `Update()` 帧中间直接 `SaveGame()`，改成打标记、帧首统一落盘。
- 读档时 `streak` 也不回退。
- 限制池复查：**「不能使用扳手」永久移出**（武器系统下线后扳手是唯一工具，
  禁掉它玩家只会以为按键坏了）；「怪物不上小地图」改成
  **「改造树的感知系失效」**（它实际只关两个节点）。

### 修复

- **每日限制泄漏到手电**：战役的「手电关不掉」先判且直接 `return`，
  把每日限制整个绕过。改成固定优先级 **禁止 > 强制 > 自由**。
- **手电禁用提示误导**：买了「抢救」天赋永久禁灯，提示却写「今天不能开手电」。
  现在分三种原因显示。
- **HUD 日游行和 LEVEL 行重叠**（两行都画在 `UIS(18)`）。日游行排到整列之后。
- **局内改造树三个操作问题**：空格被「校准」拦截并 `return`（买不了东西）；
  每次按键都强制把画布居中（买完位移、左右移动看起来没反应）。
  现在树页不吃空格，只在切页时居中一次。
- **投掷物半空碎裂、没有效果**：投石被怪物吃掉就销毁（而 `NO_COMBAT`
  下它不造成伤害），以及寿命到期只炸碎片不结算。现在投石穿过怪物继续飞，
  所有终止路径都走同一套效果。
- **荧光棒卡进墙里丢失建模**：点判定 ＋ 出手后 0.15 秒无碰撞 →
  贴墙扔会埋进墙里。现在有实体半径（中心＋四向）、撞墙**反弹**、卡墙自救。
- **回响触发机制**：原来只有「落在地面」计数，撞墙/打怪/超时全不算 ——
  走廊里扔半天不回响。现在四个出口都计数。
- **G 键投石超模**：技能描述写着 `8s cd`，实现里一个冷却都没有，可以无限放。
  现在补上 8 秒并给冷却提示。
- **信号枪 / 符印建模残留**：这两个武器系统早就下线，模型却还在，
  而每日模式 `curWeapon = dailySeed % WPN_COUNT` 会随机抽到、把它画到屏幕上。
  两个精灵与烘焙函数一并删除，手持模型钉死为扳手。
- **5 个死击杀计数**（`totalKills / killsWrench / killsBottle / floorKills / benchKills`）：
  本作没有击杀手段，它们一次都不会 +1。
- **图鉴成就 6 → 7 种**（宝箱怪加入之后文案过时）。

## v2.3.8 更新 · 2026-11-05

第七只怪、两种新锁型、回声弹重做，以及一批平衡与界面修复。

### 第七只威胁：宝箱怪

一个「看起来比普通箱子值钱」的箱子 —— **惹它才有钱，绕开一分没有**。

- 伪装态是暗金包边、双层歪锁扣、会轻微微起伏的箱子；现形是「箱子站起来」：
  掀开的盖子 + 四条短腿 + 横贯上部的宽口。
- 三条应对：**按住 E 翻找到 60% 会被咬**（−25 理智，不吃抗性）；
  **扳手敲**直接逼现形且免挨咬；**回声箭**只打标记、不惊动。
- 现形后追 8 秒，沿途每 2 秒发一次 12 格噪音 —— 它真正的危险是把听声鬼引过来。
- 甩掉后原地留下**空壳**：`150 + 50×层` 金币 + 1 保险丝 + 1 道具，结算再 +400 分。
- **打不死**：本作怪物都不可杀，扳手只能逼它现形和击退。
- 第 3 层起 12%、第 6 层起 20%，每层 1 只；保险丝箱永远不会变成宝箱怪。

### 两种新锁型

- **过载 OVERLOAD**：按住充能、越充越快，在绿区松手。过红线会爆火花（−10 电量、−3 理智、噪音）。
- **锯锁 SAW**：按住来回拖，要跟着节拍标记的方向锯。逆拍掉进度，拖太猛会**卡锯**并发噪音。
- 局内锁型改成**发牌**：每层洗一副 6 张按序发，同层不重复、跨层必然覆盖全部 6 种。

### 回声弹重做：资源雷达

- 半径 3 → **10 格**；标记**容器 30 秒**（保险丝金色 / 宝箱怪红闪 / 普通白色）
  与**活物 5 秒**（红菱形）。
- 落地自带 **20 格噪音** —— 它是敲门，不是偷看。

### 平衡

- **上锁箱子按层递增**：第 1 层 0%、第 2 层 5%、之后每层 +9%，封顶 **70%**。
  保险丝改成「锁箱优先 + 永远留 1 根不锁」。
- **校准小游戏重新定价**：奖励随层数成长（完美 `12+2×层` 理智 / `20+4×层` 金币 / +15 电量），
  每层限 **3 次**、冷却 **30 秒**（原来每层 99 次 = 可以无限刷理智）。
- **大地图不再耗电**且打开时暂停；新增第 6 条局内强化「小地图省电」
  （每级 −2 个百分点，3 级封顶：10 / 8 / 6 / 4 每秒）。

### 修复

- **商店 LEAVE 行用鼠标点没反应**：强化 / 改装 / 休息三页的 LEAVE 行直接 `return`，
  只有商店页写了 `ShopLeave()`。现在四个页面都能点。
- **离开商店后视角瞬间翻转 180°**：菜单里滑过的鼠标位移被当成一次视角输入。
- **走到出口却通不了关**：进入半径 0.55 → **1.05 格**（一格宽就是 1.0，旧值判定不到）。
- **道具栏滚轮卡死**：滚轮挪到空槽又被每帧校验拽回第一个有货的槽，中间有空格就出不去。
- 三条 HUD 提示叠字（`BRESE 272 HIDE`）、安全屋分组线横穿页签列、改造树价格压字。

### 存档

- `SAVE_VERSION` 28 → **29**；v25 / v26 / v27 / v28 全部按前缀迁移，不丢进度。

## 逃生玩法

探索迷宫 → 搜箱补给、找保险丝 → 配电箱通电 → 选择撤离或深入 → 结算入银行。

主线终点是 **第 8 层**。中途到达已通电的出口，可以按 `1` 撤离并结束本局，
或按 `2` 继续深入；最终层完成后进入通关结算。理智归零则本局失败。

手电提供视野，也会引来追光鬼；冲刺、搜箱和摇电会制造噪音。
找电池或手摇发电可以补电，柜子和垃圾桶等藏身点提供暂时的喘息机会。
被清道夫损坏的藏身点可花金币修复。搜寻过程中还有锁箱谜题、随机词条、主题和特殊事件。

### 七种威胁

| 怪物 | 主要威胁 | 应对思路 |
|---|---|---|
| 听声鬼 | 追踪噪音与可疑点 | 控制声音，用远处落点转移注意力 |
| 追光鬼 | 追踪手电等光源 | 管理开灯时机，利用遮挡和藏身点 |
| 面相鬼 | 靠近后突袭，触发 QTE | 留意征兆，按屏幕提示躲避或挣脱 |
| 拾荒者 | 盯上携带的金币并偷钱 | 管理携带额，使用钱袋转移目标 |
| 清道夫 | 停留或反复躲藏引来追查，会撬坏藏身点 | 持续换路线，避免依赖同一个藏身点 |
| 守门人 | 通电后威胁出口路线 | 观察它的位置和状态，规划突围时机 |
| 宝箱怪 | 伪装成华丽箱子，翻找时咬人 | 用回声箭确认、扳手敲出原形，或直接绕开 |

扳手用于**击退与硬直**，为逃生争取窗口；它不会击杀猎手。
投掷物有光球、投石、烟雾、胶水、回声和诱饵六类。
诱饵通过右键放在脚下，再按 `C` 激活；回声落地后会把 10 格内的容器与活物标到小地图上（容器 30 秒、活物 5 秒），但它自身会发出 20 格噪音。

### 金币、银行与构筑

金币分为跨局的**银行存款**和本局的**携带金币**。开局在银行决定携带比例，
局内金币用于补给和强化；成功撤离时，利润受携带、深度、表现和协议等倍率影响。
死亡按当时携带金币的 **35%** 返还，不享受成功撤离的收益倍率。

携带额对应 **T0～T15 共 16 档强度**，影响听觉与追踪机制；金币档位不会直接增加怪物移速。
按住 `K` 可选择丢出钱袋的比例，松开后丢出，靠近按 `E` 可捡回。

| 成长系统 | 花费与保留范围 | 当前内容 |
|---|---|---|
| 大厅技能树 | 花银行金币，跨局保留 | 30 个放射布局节点，含主枝、跨支联动与可切换顶点；当前满树预算 132,000 金币 |
| 局内改造树 | 花本局金币，新局清空、换层保留 | 体／光／心／械四类，共 20 节点；每类顶点二选一，强化会增加威胁值 |
| 局内强化与三选一 | 服务于本局构筑 | 基础属性强化，以及过层触发的技能／遗物选择 |

两棵树支持滚轮缩放和拖拽平移。大厅或局内树页面中，**两秒内连按两次 `R`** 可退款重置对应树；
大厅重置保留中心起点。132,000 是当前价格预算，仍需根据真实游玩数据校准。

局内按 `T` 打开商店与强化界面，`Tab` 翻页；非树页也可用左右键切页。
商品页 `R` 每层免费刷新一次。商店和出口选择等模态界面会暂停相应对局推进。

### 模式与进度

| 模式 | 内容 |
|---|---|
| 主线 | 随机迷宫、资源管理与撤离选择，第 8 层完成通关 |
| 无尽 | 解锁后继续深入，保留独立的最高层数与成绩记录 |

战役各关层数为 `1 / 2 / 1 / 3 / 1`，分别奖励 `3000 / 4000 / 6000 / 8000 / 15000` 金币，

## 编译

需要 Windows x64、MinGW-w64 GCC 和 `windres`。在仓库根目录执行。

Git Bash / MSYS2 UCRT64：

```bash
windres res/canity.rc -O coff -o res/canity_res.o
gcc src/*.c src/steam/*.c res/canity_res.o -Iinclude \
    -std=c99 -O2 -Wall -Wextra -Werror \
    -lgdi32 -luser32 -lwinmm -mwindows -o canity.exe
```

PowerShell（显式枚举子目录中的源文件）：

```powershell
windres res/canity.rc -O coff -o res/canity_res.o
if ($LASTEXITCODE -ne 0) { throw 'Resource build failed' }
$sources = Get-ChildItem -LiteralPath src -Recurse -Filter *.c |
    Sort-Object FullName | ForEach-Object { $_.FullName }
gcc @sources res/canity_res.o -Iinclude -std=c99 -O2 -Wall -Wextra -Werror `
    -lgdi32 -luser32 -lwinmm -mwindows -o canity.exe
if ($LASTEXITCODE -ne 0) { throw 'Game build failed' }
```

必须包含 `src/steam/*.c`，即使 Steam 默认关闭，也需要它提供本地封装实现。
资源文件包含图标、版本信息和运行清单；`-O2` 用于软件渲染优化，`-lwinmm` 用于计时与音频。
[GitHub 发布工作流](.github/workflows/release.yml) 在推送 `v*` 标签时构建并生成 Windows ZIP 包。

详见 [修复与升级说明](docs/codex_upgrade_2.3.3.md)。自动检查不能替代完整手玩和界面视觉验收。

## 已知问题与后续方向

v2.3.5 修掉了 2.3.4 列出的三条界面问题：技能树节点名改用小字、详情条不再被节点压住、
标题不再重影；HUD 的每日横幅位置也已调整。仍然存在：

- 技能树默认缩放 0.45x，中文长节点名只能显示两三个字（可滚轮放大）。
- 技能节点的描述文案尚未汉化（节点名与分支名已翻）。
- 守门人的 `WD_RUSH` 状态在上游代码里就从未被赋值过，属历史死状态。
- 清道夫与拾荒者是**独立 AI**，不参与 `MonsterCollect`，因此不吃烟雾 —— 有意为之。

低内部渲染分辨率、不同 DPI、长中文和模态组合仍需实机视觉检查。

后续建议按以下方向推进；这些是规划，尚不作为当前已交付功能：

- 先收尾界面可读性，再增加空间音效、可辨识的房间与环境叙事，形成恐怖节奏。
- 让潜行、机动、击退和冒险构筑各有取舍，并加深投掷物组合的用途与代价。
- 探索辅助供电分配与下一层情报，让“撤离还是深入”有更多判断依据，保证必需保险丝足够。
- 让特殊事件改变可见、可听的环境与路线选择；事件视野倍率等预留项仍需补齐接线和验收。
