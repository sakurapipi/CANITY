# CANITY

纯 C / Win32 GDI 编写的第一人称像素恐怖逃生游戏。
射线投射、纹理采样、Z-Buffer 和后处理都由 CPU 在内存位图中完成，无需 OpenGL 或 DirectX。
默认画面、音效与背景音乐都由代码程序化生成；Windows x64 单机版可直接运行，也可以往 `music/` 放文件替换配乐。

当前版本：**v2.3.6 · 2026-11-04**。下载见 [Releases](https://github.com/sakurapipi/CANITY/releases/latest)，完整版本记录见 [CHANGELOG](CHANGELOG.md)。

## 逃生玩法

探索迷宫 → 搜箱补给、找保险丝 → 配电箱通电 → 选择撤离或深入 → 结算入银行。

主线终点是 **第 8 层**。中途到达已通电的出口，可以按 `1` 撤离并结束本局，
或按 `2` 继续深入；最终层完成后进入通关结算。理智归零则本局失败。

手电提供视野，也会引来追光鬼；冲刺、搜箱和摇电会制造噪音。
找电池或手摇发电可以补电，柜子和垃圾桶等藏身点提供暂时的喘息机会。
被清道夫损坏的藏身点可花金币修复。搜寻过程中还有锁箱谜题、随机词条、主题和特殊事件。

### 六种威胁

| 怪物 | 主要威胁 | 应对思路 |
|---|---|---|
| 听声鬼 | 追踪噪音与可疑点 | 控制声音，用远处落点转移注意力 |
| 追光鬼 | 追踪手电等光源 | 管理开灯时机，利用遮挡和藏身点 |
| 面相鬼 | 靠近后突袭，触发 QTE | 留意征兆，按屏幕提示躲避或挣脱 |
| 拾荒者 | 盯上携带的金币并偷钱 | 管理携带额，使用钱袋转移目标 |
| 清道夫 | 停留或反复躲藏引来追查，会撬坏藏身点 | 持续换路线，避免依赖同一个藏身点 |
| 守门人 | 通电后威胁出口路线 | 观察它的位置和状态，规划突围时机 |

扳手用于**击退与硬直**，为逃生争取窗口；它不会击杀猎手。
投掷物有光球、投石、烟雾、胶水、回声和诱饵六类。
诱饵通过右键放在脚下，再按 `C` 激活；回声以道具和可疑点效果参与引导怪物。

### 金币、银行与构筑

金币分为跨局的**银行存款**和本局的**携带金币**。开局在银行决定携带比例，
局内金币用于补给和强化；成功撤离时，利润受携带、深度、表现和协议等倍率影响。
死亡按当时携带金币的 **35%** 返还，不享受成功撤离的收益倍率。

携带额对应 **T0～T15 共 16 档强度**，影响听觉与追踪机制；金币档位不会直接增加怪物移速。
按住 `K` 可选择丢出钱袋的比例，松开后丢出，靠近按 `E` 可捡回。

| 成长系统 | 花费与保留范围 | 当前内容 |
|---|---|---|
| 大厅技能树 | 花银行金币，跨局保留 | 30 个放射布局节点，含主枝、跨支联动与可切换顶点；当前满树预算 132,000 金币 |
| 局内改造树 | 花本局金币，新局清空、换层保留 | 体／光／心／械四类，共 20 节点；每类顶点二选一，强化会增加威胁值 |
| 局内强化与三选一 | 服务于本局构筑 | 基础属性强化，以及过层触发的技能／遗物选择 |

两棵树支持滚轮缩放和拖拽平移。大厅或局内树页面中，**两秒内连按两次 `R`** 可退款重置对应树；
大厅重置保留中心起点。132,000 是当前价格预算，仍需根据真实游玩数据校准。

局内按 `T` 打开商店与强化界面，`Tab` 翻页；非树页也可用左右键切页。
商品页 `R` 每层免费刷新一次。商店和出口选择等模态界面会暂停相应对局推进。

### 模式与进度

| 模式 | 内容 |
|---|---|
| 主线 | 随机迷宫、资源管理与撤离选择，第 8 层完成通关 |
| 无尽 | 解锁后继续深入，保留独立的最高层数与成绩记录 |
| 每日挑战 | 按日期组合目标、修正和限制；任务有 8 类目标，限制仅作用于每日模式 |
| 战役 | 五关分别为黑暗工厂、无声区、守门人之城、贪婪深渊、最后一道门，共 8 层 |
| 训练营 | 熟悉基础操作、道具与怪物 |

战役各关层数为 `1 / 2 / 1 / 3 / 1`，分别奖励 `3000 / 4000 / 6000 / 8000 / 15000` 金币，
逐关切换特殊规则，最后一关需要 8 根保险丝。
成就、图鉴遭遇／逃脱／被抓记录和每日任务进度可跨启动保留；图鉴随认识进度分阶段揭示。

## 音乐与存档

背景音乐默认是内置程序化配乐：主菜单 Lull、探索 Hollow、追逐 Fracture、安全屋 Crawl，实时合成、无缝续写；胜利和失败只留音效。想换成自己的曲子，在 `canity.exe` 旁建立 `music/`，放入以下文件：

| 文件名 | 场景 |
|---|---|
| `menu.mp3` / `menu.wav` | 主菜单 |
| `explore.mp3` / `explore.wav` | 探索 |
| `chase.mp3` / `chase.wav` | 追逐 |
| `safe.mp3` / `safe.wav` | 商店／安全界面 |
| `victory.mp3` / `victory.wav` | 成功撤离 |
| `defeat.mp3` / `defeat.wav` | 失败 |

可只放部分曲目；放任意一个文件后游戏整体切换到文件模式，同名时优先 MP3，缺少文件的场景保持无背景音乐。清空 `music/` 或设置 `CANITY_MUSIC=builtin` 可回到内置曲目。
播放由 Windows MCI 提供，实际支持取决于文件编码和系统解码能力。
模块已接场景切换、音量、暂停与事件触发的临时压低，详情见 [音乐协议 v1](docs/music_protocol.md)。

当前存档格式为 **27**。代码可向下兼容 **v24（2.3.3 及更早）/ v25 / v26**：读档时按版本和文件长度迁移，金币、银行、遗物、藏身点、局内改造与运行进度都会保留；2.3.4 重建了成就表，旧成就 ID 无法一一对应，迁移时清零以免误弹成就。更老的版本仍会归档为 `.v<版本>.bak` 并按无存档处理，不覆盖原文件。
测试可设置 `CANITY_DATA_DIR` 指向独立目录，避免写入玩家存档。

## 编译

需要 Windows x64、MinGW-w64 GCC 和 `windres`。在仓库根目录执行。

Git Bash / MSYS2 UCRT64：

```bash
windres res/canity.rc -O coff -o res/canity_res.o
gcc src/*.c src/steam/*.c res/canity_res.o -Iinclude \
    -std=c99 -O2 -Wall -Wextra -Werror \
    -lgdi32 -luser32 -lwinmm -mwindows -o canity.exe
```

PowerShell（显式枚举子目录中的源文件）：

```powershell
windres res/canity.rc -O coff -o res/canity_res.o
if ($LASTEXITCODE -ne 0) { throw 'Resource build failed' }
$sources = Get-ChildItem -LiteralPath src -Recurse -Filter *.c |
    Sort-Object FullName | ForEach-Object { $_.FullName }
gcc @sources res/canity_res.o -Iinclude -std=c99 -O2 -Wall -Wextra -Werror `
    -lgdi32 -luser32 -lwinmm -mwindows -o canity.exe
if ($LASTEXITCODE -ne 0) { throw 'Game build failed' }
```

必须包含 `src/steam/*.c`，即使 Steam 默认关闭，也需要它提供本地封装实现。
资源文件包含图标、版本信息和运行清单；`-O2` 用于软件渲染优化，`-lwinmm` 用于计时与音频。
[GitHub 发布工作流](.github/workflows/release.yml) 在推送 `v*` 标签时构建并生成 Windows ZIP 包。

## 已知问题与后续方向

v2.3.5 修掉了 2.3.4 列出的三条界面问题：技能树节点名改用小字、详情条不再被节点压住、
标题不再重影；HUD 的每日横幅位置也已调整。仍然存在：

- 技能树默认缩放 0.45x，中文长节点名只能显示两三个字（可滚轮放大）。
- 技能节点的描述文案尚未汉化（节点名与分支名已翻）。
- 守门人的 `WD_RUSH` 状态在上游代码里就从未被赋值过，属历史死状态。
- 清道夫与拾荒者是**独立 AI**，不参与 `MonsterCollect`，因此不吃烟雾 —— 有意为之。

低内部渲染分辨率、不同 DPI、长中文和模态组合仍需实机视觉检查。

后续建议按以下方向推进；这些是规划，尚不作为当前已交付功能：

- 先收尾界面可读性，再增加空间音效、可辨识的房间与环境叙事，形成恐怖节奏。
- 让潜行、机动、击退和冒险构筑各有取舍，并加深投掷物组合的用途与代价。
- 探索辅助供电分配与下一层情报，让“撤离还是深入”有更多判断依据，保证必需保险丝足够。
- 让特殊事件改变可见、可听的环境与路线选择；事件视野倍率等预留项仍需补齐接线和验收。
