# CANITY

[![CI](https://github.com/sakurapipi/CANITY/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/sakurapipi/CANITY/actions/workflows/ci.yml)

一款以探索、声音、光线与资源取舍为核心的第一人称像素恐怖逃生游戏，使用 C99 编写。

**当前源码版本：2.4.3 · 存档格式：v45 · 地图：36×36 · 容器槽：12。**

Windows 桌面版与 WebAssembly 网页版共用游戏规则。射线投射、纹理采样、深度遮挡与后处理由 CPU 软件渲染完成，无需 OpenGL 或 DirectX 图形接口。怪物造型与场景贴图使用程序化生成；配乐随包提供 MP3，另有内置合成回退。

## 开始游戏

### Windows

正式版 Windows 包完整解压后，双击 **canity.exe**，无需 BAT 或 DAT。MP3音乐已嵌入程序，首次运行会缓存到用户目录；请保留随包许可证。

正式版单 EXE在未指定 `CANITY_DATA_DIR` 时使用 `%LOCALAPPDATA%/CANITY/saves/`，已设置该变量时保留用户指定位置。旧版便携包的 `saves/` 不会自动被覆盖。升级前请备份自己的存档，不要用测试目录覆盖玩家数据。

### 网页与手机

Tab小地图按住打开、松开关闭；M切换大地图。全屏可用顶部“进入全屏／退出全屏”按钮往返，浏览器支持时也可按Esc退出。手机扳手按住蓄力、松开挥击；两棵技能树支持触摸平移与加减缩放。

普通网页包包含 `index.html`、`index.js`、`index.wasm` 和音乐资源。请通过 HTTP 服务打开：

```sh
# 在解压后的网页目录运行
python -m http.server 8080
```

在电脑浏览器访问 `http://127.0.0.1:8080/`。手机可在同一网络访问电脑的局域网地址，推荐横屏，使用触控移动、转向与动作按钮。

单文件构建为 `standalone.html`，内嵌游戏与配乐资源，可直接尝试打开；手机本地文件支持取决于浏览器，无法加载时请使用 HTTP 版本。浏览器通常需要一次点击或按键才能启用音频。

## 玩法

探索迷宫，寻找金币、补给与保险丝，为出口通电，再决定撤离还是继续深入。手电能帮助辨路，也可能吸引追光怪；移动、搜查与交互产生的声音会影响听声怪。理智、电量、携带金币与威胁共同决定行动空间。

### 成长与经济

- **局外技能树**：幽灵、掠夺者、反击者三条成长方向，围绕潜行、风险收益与遭遇反制展开；使用银行金币，跨局保留。
- **局内属性树与补给**：花费本局金币，构筑随本局推进。局内商店只能在藏身点打开，补给价格会随进程上涨。
- **修整服务**：不限制使用次数，重复使用价格逐次翻倍。
- **银行与威胁**：决定本局携带金币，平衡收益与危险；银行存款和本局钱包分别管理。
- **音乐小游戏**：暂停被动理智与电量消耗，正确操作及连击带来恢复；累计超过五次失误会中断并退出藏身点。每层小游戏金币奖励封顶 90，达到上限后仍可恢复。
- **奖励来源**：搜查容器、完成小游戏、满足严格判据的脱离追逐与通关。具体金额、门槛和倍率以当前游戏说明为准。

两棵技能树支持鼠标选择、拖动和缩放；购买支持鼠标及键盘确认。节点解锁需要满足实际前置条件，连接线与详情面板用于提示发展路径。

### 怪物与环境

听声怪、追光怪、缚丝蛛、拾荒者、清道夫、守门人与宝箱怪各有行为与应对方式。出场受深度与强度门槛约束，首层保留较低压力；图鉴条目数不等于全部实体或个体数量。

怪物具有细节贴图与微动态。低理智会影响画面与音乐，关闭手电后环境更暗；高威胁界面采用血红、破损与失序的视觉反馈。主题房拥有各自家具、特殊控制闸与事件，奖励容器可能需要解谜开锁。

### 模式

| 模式 | 内容 |
|---|---|
| 主线与无尽 | 完成撤离目标，或继续深入追求更高收益与风险 |
| 战役 | 五个规则主题关卡，共八层，逐步考验光线、声音与撤离决策 |
| 每日挑战 | 按日期轮换十四个设计场景，组合目标、修正与限制 |
| 训练营 | 练习基础操作；按 B 进入独立引导层，完成教学获得启动资金 |

已有进行中的对局时，开启替代对局会要求确认，避免误操作覆盖进度。

## 操作与设置

以游戏内的按键绑定和当前界面提示为准。基础操作包括 WASD 移动、鼠标转向、Shift 冲刺、E 交互、F 手电、长按 R 摇电、左键扳手、右键投掷、T 藏身点商店和 Esc 暂停／返回。

设置可调整画质、帧数、音量和键位；新配置默认自动画质、无上限帧数，已有玩家配置会保留。网页触控与桌面输入最终调用共用的游戏逻辑。

## 存档与音频

当前格式为 **v45**，追加保存钱袋、未追回赃款与单局反击消耗状态，保留 v25–v44 迁移。读取包含旧版本迁移与位置恢复逻辑；保存前保留 `.bak`，部分迁移还会生成带版本的备份。兼容范围、字段处理及失败策略以 [存档实现](src/save.c) 为准，构造夹具不能替代真实历史玩家存档验收。

桌面存档位置由启动方式及 `CANITY_DATA_DIR` 决定。网页使用浏览器持久化存储；清除站点数据可能删除进度，请保留导出的存档或独立备份。

桌面与网页均有背景音乐。`music/` 包含菜单、探索、追逐、藏身点、胜利和失败等 MP3 及谱面；音乐随场景和理智状态调度。桌面支持 `CANITY_MUSIC=files` 或 `builtin` 选择文件／内置音乐。分发时请保留音乐资源和许可证。

## 从源码构建

### Windows

需要 Python 3、MinGW-w64 GCC 与 `windres`。工具默认从 PATH 查找，也可设置 `CANITY_GCC`、`CANITY_WINDRES` 指向可执行文件。

```sh
# 编译、独立运行全部测试域，并执行结构与内容检查
python -X utf8 tools/build_validate.py

# 只编译，不构成验证通过
python -X utf8 tools/build_validate.py --build-only
```

权威源文件清单由 `tools/build_sources.py` 管理，包含子目录和平台后端筛选，请勿用手写的 `src/*.c` 替代。

### WebAssembly

需要 Emscripten，可通过 `CANITY_EMSDK`、`EMSDK` 或 PATH 提供工具链：

```sh
python -X utf8 tools/build_web.py
python -X utf8 tools/build_web.py --single
```

输出位于 `web/dist/`。普通网页构建需一同部署音乐资源，单文件构建会内嵌资源。

### 生成运行包

先完成对应平台构建，再打包；下列命令使用最近一次完整验证报告：

```sh
python -X utf8 tools/package_stable.py --validation-report work/codex-build/validation-summary.json --source-commit <完整提交SHA>
python -X utf8 tools/package_web_mobile.py
```

`--include-web` 要求网页构建已存在。运行包记录源码、资源和验证摘要；报告与当前验证输入不匹配时拒绝套用。生成安装包不等于已经完成真实桌面或手机验收。

## 2.4.2 正式版验证范围

完整 C99 编译、全部 15 个隔离运行域及内容/分区检查纳入发布门禁。新增训练经济隔离、档位切换、备份保护、历史 v31/v32 布局、每日样本续存与垂直视角回归。Edge 浏览器专项覆盖 33 项输入、触控、地图、全屏、后台暂停、存档导出及混合设备交互；手机部分使用浏览器模拟。

## 项目结构

| 位置 | 职责 |
|---|---|
| `src/game.c`、`src/loop_*.c` | 调度、关卡、输入、对局与菜单流程 |
| `include/*_api.h`、各模块契约头 | 模块间公开接口；`game.h` 保持私有边界 |
| `src/render.c`、`src/sprites.c`、`src/ui*.c` | 软件渲染、程序化造型、界面 |
| `src/entity.c`、各怪物模块 | 感知、追逐、攻击与特殊行为 |
| `src/skills.c`、`src/bench.c`、`src/shop.c` | 局外成长、局内属性树、补给与服务 |
| `src/campaign.c`、`src/daily.c`、`src/room_template.c` | 模式、主题房与事件规则 |
| `src/save.c`、`src/save/` | 存档、迁移与平台存储边界 |
| `src/platform/` | 桌面与网页平台实现 |
| `src/music*.c`、`src/audio*.c`、`music/` | 音乐调度、音效、配乐与谱面 |
| `tests/`、`tools/` | 运行期用例、构建、内容与架构检查、打包 |
| `l10n/`、`web/`、`docs/` | 本地化、网页外壳与设计资料 |

进一步阅读：[模块文档](docs/modules/README.md)、[Web 说明](docs/WEB.md)、[创作与体验约束](include/art_direction.h)。历史文档记录当时设计，不应覆盖当前源码行为。

Steam 封装默认关闭，本地运行不依赖 Steam；线上成就、云存档等能力仍需 App ID、运行库及后台配置，不能视为已完成线上验证。
