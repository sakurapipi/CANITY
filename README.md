# CANITY

纯 C 编写的第一人称像素恐怖逃生游戏。

射线投射、纹理采样、Z-Buffer 和后处理全部由 CPU 在内存位图中完成，**不需要 OpenGL / DirectX / 任何图形库**。
游戏里的贴图、模型、音效、配乐都是**代码程序化生成**的 —— 仓库里没有美术素材文件，只有一张程序图标。

当前版本 **v2.4.2**（双端稳定性补丁）。下载见 [Releases](https://github.com/sakurapipi/CANITY/releases/latest)。

> v2.4.2 不改存档结构：仍是 **v34**，v2.3.6 之后的存档可以直接读，
> 旧版本会在迁移前自动留一份 `.v<版本>.bak`。

## 三个版本

同一份源码，三种交付形态：

| 版本 | 文件 | 说明 |
|---|---|---|
| **Windows 桌面版** | `CANITY_v2.4.2_win64.zip` | 解压双击 `canity.exe`。需要 64 位 Windows |
| **网页版** | `CANITY_v2.4.2_web.zip` | 解压后在该目录起 HTTP 服务，浏览器打开 |
| **网页版单文件** | `CANITY_v2.4.2_web_single.html` | 约 1.6 MB，wasm 已内联，**双击即玩** |

### 网页版怎么开

不能直接双击 `index.html` —— 浏览器会拦掉 wasm 的 fetch。需要起一个本地服务：

```
cd 解压目录
python -m http.server 8080
```

然后打开 `http://127.0.0.1:8080/`

嫌麻烦就用**单文件版**：双击 `CANITY_v2.4.2_web_single.html` 即可，不需要服务器。

手机上横屏打开单文件版：左半屏拖动移动，右半屏拖动转视角，右侧是动作键。

## 逃生玩法

探索迷宫 → 搜箱补给、找保险丝 → 配电箱通电 → 选择撤离或深入 → 结算入银行。

主线终点是 **第 8 层**。中途到达已通电的出口，可以按 `1` 撤离结束本局，或按 `2` 继续深入。
理智归零则本局失败。

手电提供视野，也会引来追光鬼；冲刺、搜箱和摇电会制造噪音。
找电池或手摇发电可以补电，柜子和垃圾桶等藏身点提供暂时的喘息机会。
被清道夫损坏的藏身点可花金币修复。

### 七种威胁

| 怪物 | 主要威胁 | 应对思路 |
|---|---|---|
| 听声鬼 | 追踪噪音与可疑点 | 控制声音，用远处落点转移注意力 |
| 追光鬼 | 追踪手电等光源 | 管理开灯时机，利用遮挡和藏身点 |
| 缚丝蛛 | 吐丝缠住玩家，5 秒无法行动 | 连按挣脱（每次 -0.5 秒，最快 1 秒）；**扳手砸中它会让它消失 30 秒** |
| 拾荒者 | 盯上携带的金币并偷钱 | 管理携带额，使用钱袋转移目标 |
| 清道夫 | 停留或反复躲藏引来追查，会撬坏藏身点 | 持续换路线，避免依赖同一个藏身点 |
| 守门人 | 通电后威胁出口路线 | 观察它的位置和状态，规划突围时机 |
| 宝箱怪 | 伪装成华丽箱子，翻找时咬人 | 用回声弹确认、扳手敲出原形，或直接绕开 |

缚丝蛛从第 4 层起出现，出现率 **20% + 每层 5%**（封顶 60%），大约每 2~3 层遇到一只。

扳手用于**击退与硬直**，为逃生争取窗口；它不会击杀猎手。

### 投掷物

| 槽 | 名称 | 效果 |
|---|---|---|
| 1 | 照明弹 | 落地发光 25 秒，**站在光里恢复理智**（1.5/秒，单根上限 12，每层 24） |
| 2 | 投石 | 砸锁箱、制造 8~20 噪音 |
| 3 | 烟雾弹 | 半径 3.6 格，云内敌人丢失目标 |
| 4 | 胶水 | 半径 2.5 格，敌人移速 ×0.2，持续 6 秒 |
| 5 | 回声弹 | 半径 10 格标记容器（30 秒）与活物（5 秒），**自身发出 20 格噪音** |
| 6 | 诱饵 | 右键放置，`C` 激活，每 1.5 秒叫一次，半径 20 格 |
| 7 | 相位信标 | 投出后成为回溯点，`Q` 传送，2 次 |

### 主题房间

房间按**深度分层**出现，每一段深度的场景风格是统一的：

| 层数 | 可能出现的主题 |
|---|---|
| 1~3 | 砖墙 / 监狱 |
| 4~6 | 冰窖 / 病房 |
| 7~9 | 锈工厂 / 地狱 |
| 10 起 | 血肉洞窟 / 锈工厂 |

七种主题各有独立的墙面腰线剖面（踢脚线、双横栏、顶部压边、粗腰带……），
站在房间里一眼能分清这是什么空间。

房间里的**控制闸**各有独特效果，悬停时会显示"拉下会发生什么"：
塌方重掷本层 / 买断整仓 + 金币翻倍 / 通电 20 秒 / 回满理智但留下血迹 /
砸穿一堵墙 / 血祭加速 / 全场敌人静止。

### 金币、银行与构筑

金币分为跨局的**银行存款**和本局的**携带金币**。开局在银行决定携带比例。
成功撤离时利润受携带、深度、表现等倍率影响；死亡按携带金币的 **35%** 返还。

| 成长系统 | 花费与保留范围 |
|---|---|
| 大厅技能树 | 花银行金币，跨局保留，30 个放射布局节点 |
| 局内改造树 | 花本局金币，新局清空、换层保留，20 节点 |
| 局内强化与三选一 | 过层触发的技能／遗物选择 |

两棵树支持滚轮缩放和拖拽平移；技能树左下角另有 `+` / `-` 缩放按钮。
**两秒内连按两次 `R`** 可退款重置对应树。局内按 `T` 打开商店，`Tab` 翻页。

### 模式

| 模式 | 内容 |
|---|---|
| 主线 | 随机迷宫、资源管理，第 8 层完成通关 |
| 无尽 | 解锁后继续深入 |
| 每日挑战 | 按日期组合目标、修正和限制 |
| 战役 | 五关，共 8 层，逐关切换特殊规则 |
| 训练营 | 熟悉基础操作、道具与怪物 |

## 存档

当前存档格式为 **34**。代码向下兼容旧版本：读档时按版本和文件长度迁移，
金币、银行、遗物、藏身点、局内改造与运行进度都会保留。
更老的版本会归档为 `.v<版本>.bak` 并按无存档处理，不覆盖原文件。

存档位置：

- **Windows**：`canity.exe` 同目录的 `canity0.sav`
- **网页版**：`localStorage`

测试可设置 `CANITY_DATA_DIR` 指向独立目录，避免写入玩家存档。

## 音乐与音效

**桌面版**：背景音乐默认是内置程序化配乐（主菜单 / 探索 / 追逐 / 安全屋），实时合成、无缝续写。
想换成自己的曲子，在 `canity.exe` 旁建立 `music/`，放入 `menu.mp3`、`explore.mp3`、`chase.mp3`、
`safe.mp3`、`victory.mp3`、`defeat.mp3`（也支持 `.wav`）。

**网页版**：目前没有背景音乐；音效由 **WebAudio 实时合成**，
16 种音效（脚步 / 心跳 / 拾取 / 通电 / 闸门 / 摇柄 / 尖叫 / 玻璃 / 翻找 / 投掷 /
胶水 / 回声 / 诱饵 / 守门人 / 清道夫 / 清道夫脚步）逐个按音色合成。

浏览器要求首次用户手势后才允许出声，点击或按键一次即可。

## 编译

### Windows 桌面版

需要 Windows x64、MinGW-w64 GCC 和 `windres`。

```bash
python -X utf8 tools/build_validate.py     # 编译 + 跑全部集成测试
python -X utf8 tools/package_release.py    # 生成 dist/CANITY_v<版本>_win64.zip
```

也可以直接用 gcc：

```bash
windres res/canity.rc -O coff -o res/canity_res.o
python -X utf8 tools/build_sources.py      # 打印权威源文件清单
```

> 源文件清单统一在 `tools/build_sources.py`，**不要手写 `src/*.c`**：
> 子目录（`src/save/`、`src/steam/`、`src/platform/`）必须递归包含，
> 同时要按平台排除另一个后端（见下）。

### 网页版

需要 [Emscripten](https://emscripten.org/)：

```bash
python -X utf8 tools/build_web.py            # web/dist/index.html + index.js + index.wasm
python -X utf8 tools/build_web.py --single   # web/dist/standalone.html（wasm 内联）
```

工具链查找顺序：`CANITY_EMSDK` → `EMSDK` → `~/.dsh/tools/emsdk` → PATH 上的 `emcc`。

### 测试

```bash
python -X utf8 tools/build_validate.py
# 期望输出：CANITY runtime integration: PASS (12169 checks) + ALL VALIDATION PASSED
```

集成测试会链接全部游戏目标文件跑真实运行期检查，不是字符串匹配。

## 代码与设计资料

### 分区设计

工程按"每一格只干一件事"分区，跨格只能通过头文件里的公开符号：

```
common.h   系统头（唯一入口）/ 全部常量 / 跨模块共享类型 / 纯数学工具
plat.h     平台接口：时间 / 窗口 / 呈现 / 输入 / 文件 / 音频出口
entity.h   玩家状态、状态效果、怪物
game.h     世界、关卡、规则、输入、菜单状态机、窗口过程
render.h   像素缓冲、贴图与查表、光栅、3D、精灵、地图
ui.h       字体、文字、菜单/弹窗/HUD 绘制、最终呈现
audio.h    waveOut 音频合成与混音
save.h     SaveBlob 与存档读写
```

每条规则都写进 `tools/partition_check.py` 逐条检查：

```
S1  除 common.h 外，任何 .c/.h 都不直接包含系统头
S2  只有 src/save/save_backend.c 能读写 .sav
S3  每个分区的公开符号只能由该分区自己的实现文件定义
```

**为什么要有 S3**：网页移植时曾经把 audio / music / gamepad / steam 的桩
全塞进平台层，结果平台层变成"什么都懂一点"的杂物间，改一个音频接口要动平台层。
现在桩回到各自分区，规则会一直盯着。

### 平台层

```
include/plat.h                唯一跨平台接口（无任何 Win32 类型）
src/platform/plat_win32.c     桌面后端（DIB + BitBlt + GetAsyncKeyState + 文件系统）
src/platform/plat_web.c       网页后端（canvas + localStorage）
src/main.c                    Win32 入口（WinMain + 消息循环）
src/platform/main_web.c       网页入口（main + rAF 主循环）
src/audio_web.c               音频分区的网页后端
src/music_web.c               配乐分区的网页后端
src/gamepad_web.c             手柄分区的网页后端
src/steam/steam_zone_web.c    Steam 分区的网页后端
```

游戏侧只认 `plat.h`。渲染数据流：

```
游戏写 pixels[]
   ├── 桌面：pixels 建在 DIB Section 上 -> StretchBlt
   └── 网页：pixels 是普通内存 -> ImageData -> putImageData
```

文字不需要额外处理：`ui.c` 的 `DrawUiTextRaw` 本来就是**软件点阵字**
（8×12 ASCII 表 + 12×12 中文图集），直接写 `pixels[]`。

### 目录

| 位置 | 职责 |
|---|---|
| `src/game.c`、`include/common.h`、`include/state.h` | 对局流程、公共类型、常量与共享状态 |
| `src/render.c`、`src/sprites.c`、`src/ui.c` | 软件渲染、程序化造型、界面 |

| `src/spider.c`、`src/control_effect.c` | 缚丝蛛与"被控制"层（束缚 / 挣脱 / 免疫） |
| `src/skills.c`、`src/bench.c`、`src/shop.c` | 局外技能树、局内改造树、商店 |
| `src/campaign.c`、`src/daily.c`、`src/events.c` | 战役、每日任务与特殊事件 |

## Steam 接入状态

Steam 封装已接生命周期、成就共用定义、统计、云存档和音乐控制入口，
默认 `CANITY_STEAM=0`，本地单机版不依赖 Steam。
线上功能还需要本游戏的 App ID、Steamworks 运行库和后台配置，目前未完成线上验证。

网页版没有 Steamworks，所有云同步 / 成就调用都是安全的空操作。

## 中文与字体

中文使用内置点阵，不依赖系统字体：字形来源为 **Noto Sans SC**（思源黑体，SIL OFL 1.1，可商用），
只把源码实际用到的字烘成 12/24/36/48px 单色图集，和英文点阵共用行高与缩放。
仓库不包含 TTF；若二次分发，请自行保留 Noto Sans SC 的 SIL OFL 1.1 许可证。

翻译词条统一在 [l10n/zh.tsv](l10n/zh.tsv)，改完运行 `python l10n/apply_tsv.py`。

## 已知问题与后续方向

**网页版**

- 渲染是**单线程**（WebAssembly 默认不带 pthread），比桌面版慢
- 没有背景音乐（音效有，且已带左右声像）
- 没有手柄支持
- 存档在浏览器 `localStorage` 里：清站点数据会丢，请用界面上的
  「导出存档」保存成 `.sav` 文件（可直接放进桌面版存档目录）
- 触屏第一人称 + 0.42 秒 QTE 在手机上偏难，后续会放宽 QTE 窗口

**桌面版**

- 技能树默认缩放 0.45x，中文长节点名只能显示两三个字（可滚轮或 `+` 放大）
- 技能节点的描述文案尚未汉化（节点名与分支名已翻）
- 守门人的 `WD_RUSH` 状态在上游代码里就从未被赋值过，属历史死状态
- 清道夫与拾荒者是独立 AI，不参与 `MonsterCollect`，因此不吃烟雾 —— 有意为之

低内部渲染分辨率、不同 DPI、长中文和模态组合仍需实机视觉检查。

**后续方向**

- 收尾界面可读性，再增加空间音效、可辨识的房间与环境叙事，形成恐怖节奏
- 让潜行、机动、击退和冒险构筑各有取舍，加深投掷物组合的用途与代价
- 探索辅助供电分配与下一层情报，让"撤离还是深入"有更多判断依据
