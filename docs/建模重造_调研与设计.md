## 一、结论先行：我们的做法从一开始就是错的

调研了射线投射这一脉的四个正统实现：

| 作品 | 建模方式 | 关键点 |
|---|---|---|
| **Wolfenstein 3D** | 预画 sprite，**8 个旋转角** × 若干动画帧 | 敌人从不同角度看是不同图片 |
| **Doom** | 预画 sprite（.lmp 打包），8 旋转 × 动画帧，**索引色 + 调色板查表** | 着色靠**查表**，不是逐像素浮点 |
| **Build（Duke3D）** | 同上，sprite 是"世界里贴着的平面物体" | 支持地板/天花板对齐、半透明 |
| **Quake** | 真 3D 模型（.mdl）+ 顶点动画 | 软件光栅化，另一条路 |

参考：
- Lode Vandevenne《Raycasting III: Sprites》—— C 射线投射 sprite 的权威教程
  <https://lodev.org/cgtutor/raycasting3.html>
- Doom 引擎概览 <https://en.wikipedia.org/wiki/Doom_engine>
- Build 引擎概览 <https://en.wikipedia.org/wiki/Build_(game_engine)>

**四条铁律**（我们一条都没做到）：

1. **模型是"烘"出来的图，不是每帧算出来的形状。**
   Doom 的墙面一帧要画 20 万像素，所以美术资源全部离线烘焙成索引位图；
   运行时只做「查表 + 拷像素」。
2. **着色是查表，不是浮点。**
   索引色 + 亮度档 LUT，一次内存读替代一次乘加。
3. **多角度、多帧。**
   生物至少 4~8 个朝向 × 2~4 帧动画。单张剪影是"纸片"，不是模型。
4. **第一人称武器 = 预画帧序列**（idle / walk1 / walk2 / fire / reload），
   不是代码里拼矩形。

## 二、CANITY 的现状与差距

| 项 | 现状 | 差在哪 |
|---|---|---|
| 手持武器 | 5~10 个 `VMRect` 硬拼 | 没有烘焙、没有帧动画、没有细节层 |
| 怪物 | `DrawBeastSprite` 一个函数服务 2 种怪，1 张剪影 | 没有多角度/多帧，怪和怪长得一样 |
| 场景道具 | 箱子/配电箱/出口/安全屋全是 `relX/relY` 硬编码条件 | 字符画，不是模型 |
| 着色 | 逐像素浮点乘加 + 距离雾 | 热路径上的浮点 |
| 唯一做对的 | **跳脸虫**（`g_jumperTex` + `g_jumperShade`） | 128×128 烘焙 + 64 档亮度 LUT |

**跳脸虫就是答案** —— 项目里已经有正确管线的雏形，只是只用在一个怪物上。

## 三、新管线设计

### 3.1 烘焙层（启动时跑一次）

```
BakeBegin(w, h)                 开一块画布（2× 超采样，AA 靠降采样）
  FillPoly(pts, n, col)         扫描线填充
  FillEllipse / FillRectGrad    椭圆、竖向渐变（做出体积）
  StrokePoly(pts, n, col, w)    描边（粗轮廓是"手绘感"的来源）
  Speckle(n, col, seed)         锈斑/噪点
  Glow(cx, cy, r, col, a)       加法辉光
BakeEnd() -> Sprite*            降采样成最终尺寸，透明色 = 0
```

### 3.2 运行时层

```
DrawSprite(spr, x, y, w, h, light, alpha, zTest)
  双线性采样 + 亮度查表 + alpha 混合
  zTest 时逐像素比 zBuffer（世界内的精灵用）
```

### 3.3 资源清单

| 类别 | 数量 | 帧 |
|---|---|---|
| 武器 | 3 | idle / fire 各一帧（+ 蓄力变体） |
| 手持投掷物 | 8 | 单帧（左手） |
| 怪物 | 7 | 每只 2 帧（站立/移动） |
| Boss | 3 | 复用怪物帧 + 放大 + 换色 |
| 场景道具 | 5 | 箱子 / 配电箱 / 出口门 / 安全屋 / 营火 |
| 合计 | **26 张** | 烘焙一次约 40~80 ms |

### 3.4 内存

26 张 × 128×128 × 4B ≈ 1.7 MB；亮度 LUT 26 × 32 档 ≈ 3 KB。
本机内存紧，但 1.7 MB 可接受（地图+贴图+存档加起来才 ~2 MB）。

## 四、执行顺序

1. **烘焙器 + 运行时 blit**（`src/sprites.c`）
2. **三把武器**（用户点名"很粗糙"）—— 带帧动画与开火辉光
3. **七种怪物**（每只独立剪影 + 2 帧）
4. **场景道具**
5. **UI 重做**（面板、按钮、图标全部走同一套烘焙）

## 五、验收标准

- 手持武器一眼能认出是什么，开火有可辨认的动画
- 七种怪在 8 格距离上能靠剪影分辨
- 道具不再是"一堆矩形"
- 帧时间不退化（烘焙在启动时付清，运行时只有 blit）
