### 为什么拆不动（6 轮实验的结论）

| 尝试 | 轮次 | 结果 |
|---|---|---|
| 搬单个函数 | 11、14 | ✗ 函数依赖 game.c 的 `static`，跨文件不可见 |
| 先补声明再搬 | 12 | ✓ 成 1 个（ClearKeyEdges） |
| 整簇搬（状态+函数） | 12、14 | ✓ 成 2 个（RNG、粒子） |
| 整簇搬大块 | 15 | ✗ calib 簇 165 行，依赖太多 |
| 由叶到根补原型 | 16 | ✗ |
| 程序化挑最独立函数 | 18 | ✗ 链接期重复定义 |
| 1 行函数 | 19 | ✗（失败原因未定位） |

**结论：`game.c` 里剩下的函数互相咬合，且大量依赖 `static` 状态。
能搬的"自包含簇"已经搬完了。**

要真正拆开，必须先做一次**内部接口重设计**（把上百个 static 提升为
带归属的模块接口），那是重写级的工作，不是"搬"。
