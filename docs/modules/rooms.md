# rooms：主题探索事件

## 所有者

- `room_archetype.c`：七种身份、两种紧凑布局、材料特征与版本标签；纯配置与几何。
- `map_rooms.c`：位置、连通性、生成回滚；一地标、两控制台、一特殊舱门。
- `room_theme.c`：房间绑定、环境声、计时效果；`RoomThemeState` 为唯一运行态。
- `room_actions.c`：控制台选择、资源门槛、安全换位、效果结算。
- `room_labels.c`：控制台及舱门的双语代价与后果说明。
- `sprite_room_devices.c`：七种独立地标、三种状态、门框和成对控制台。

## 契约

负数种子按区间区分紧凑布局2和宽敞布局3；正数种子走旧模板及旧生成随机调用路径。
不改变 v45 结构，准备状态复用新增专用家具编号的 `searched` 记录。
快照读档优先恢复原始地图、属性、家具及舱门；之后重建选择状态。
控制台不发奖励、不扣资源；特殊舱门在动画完成且二次门槛通过后结算一次。
门槛或目标失效时回到封闭态。实体建筑写 worldMap；普通装置不暗中阻挡寻路。
两条相机路径只为标记过的新房间采样建筑材质，不修改相机投影或 FOV。

## 用例

`tests/domains/test_rooms.c` 编写了布局通行、版本分支、准备门槛、转换互斥、
取消投资、动画期间电量不足、安全换位和重复结算用例。本轮未运行。

宽敞版本按整层材质反查房间身份，必须至少双向连通且满足低死路规则。
`floor_routes.c` 只在地形生成阶段使用：连接外围分量、完整打通短环线，保护房间墙体。
模型和控制台数量没有随房间面积增加；地图总尺寸与容器数保持不变。
