# 内容中枢与检查器体系

> 2026-11-09 建。这一批 8 轮做的东西，以及**明确欠着的两笔账**。

## 一、为什么要建这个

同一个内容的"事实"在这个项目里散在 2~4 处：

| 内容 | 之前散在哪 |
|---|---|
| 技能 | `skillDefs[]` + `kShortNames[]` + `kNodeNX/NY[]` + `kSkillList[]` |
| 图鉴 | `bestiary[]` + `bestiaryKnowledge[]` + `BESTIARY_COUNT` |
| 设置 | `settings[]` + `g_bindings[]` |
| 成就 | `g_achievements[]` + `AK_FLAG` 裸索引 |

全靠人同步。2026-11-08 就因此白加了 10 个技能节点（界面显示 1/30）。

## 二、中枢（`include/content_db.h` + `src/content_db.c`）

三个接口，所有系统只查这张表：

```c
int         ContentCount(ContentKind kind);
const void* ContentGet(ContentKind kind, int index);
int         ContentFind(ContentKind kind, const char* id);
```

五类内容，**全部已通电**（2026-11-09）：

| 种类 | 条数 | 登记函数 | 计数来源 |
|---|---|---|---|
| `CK_MONSTER` | 7 | `BestiaryRegister()` | `BESTIARY_COUNT` |
| `CK_SKILL` | 40 | `SkillRegister()` | `SKILL_COUNT` |
| `CK_SHOT` | 11 | `ShotRegister()` | `ShotSpecCount()` |
| `CK_SETTING` | 44 | `SettingsRegister()` | `SETTING_COUNT` |
| `CK_ACHIEVEMENT` | 32 | `AchievementRegister()` | `ACH_COUNT` |

**三条规矩**（写在头文件里）：

1. 不许绕过中枢自己再存一份
2. id 必须唯一（重复登记返回 -1）
3. **id 必须指向稳定存储** —— 中枢只存指针，不复制字符串

## 三、检查器（`tools/content_check.py` + `tools/checks/`）

注册制：加一个检查器 = 往 `tools/checks/` 丢一个 `check_*.py` 文件，
不用改 runner、不用改 CI。

现有 4 个，21 条断言：

| 检查器 | 查什么 |
|---|---|
| `check_skill_tables` | 技能四表是否对齐 + 总价是否等于 `SKILL_TOTAL_COST` |
| `check_bestiary` | 图鉴行数、中文名/标签、**每只怪必须有反制手段** |
| `check_bestiary_registered` | 图鉴是否登记进中枢、循环是否覆盖 `BESTIARY_COUNT` |
| `check_skill_registered` | 技能是否登记进中枢、`SkillResetAll` 是否真的调用 |

**已接进 CI 和发布闸门**（`ci.yml` 第 5 步、`release.yml` 的 gates）——
图鉴缺一只怪，现在发不出去。

## 四、生成器（`tools/content_gen.py`）

`python tools/content_gen.py skill ...` 规划 7 处修改：

```
common.h   SK_ 枚举 / SKILL_COUNT / SKILL_TOTAL_COST
skills.c   表行 / 坐标 / 短名
ui.c       kSkillList
```

已经能挡：网格满、短名超 6 字符、缺参数。

`--self-test` 会**在临时副本上真正跑一遍插入**并复查四表对齐 —— 实测通过。

## 五、数值报告（`tools/balance_report.py`）

只做「派生 + 红线 + 出表」，**不自动调平衡**：

```
技能 40 个，总价 198700，与声明一致 ✓
王冠 7 个
红线全部通过（只说明数字没崩，不说明好玩）
```

怪物速度那一段目前解析不到（常量前缀不匹配）—— 已知缺口。
