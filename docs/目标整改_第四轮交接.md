## 1. 删除三条对象名宏

common.h 不再定义 monster/monster2/monster3 对象宏，改用 `Hunter0/1/2()` 指针访问器，仍指向 monHunters 的原三个槽位。C 调用处迁移为访问器，成员读取使用普通 `Hunter0()->state` 写法；整体对象赋值保留解引用的左值语义。用户修好的 `mon` 字段不改回旧名。

新增回归源码同时声明 monster/monster2/monster3 三个结构字段，并断言访问器地址等于原数组槽位。它既覆盖编译期命名冲突，也覆盖运行时身份保持；本轮未执行。dump_symbols 的对象名相应更新为真实符号 monHunters。

## 2. 私有状态归属，不以 extern 清零指标

- loop_frame.c：原每帧更新流水线及私有阶段；诱饵按键冷却为该模块的 static，通过重置函数供开局使用。
- loop_desktop_input.c：菜单点击、键盘处理、Windows 消息分派；地图按住状态为该模块的 static。
- loop_start.c：开局队列、模式清理和初始化；待开始模式及战役阶段为该模块的 static，通过排队入口提交意图。
- loop_progress.c：本局成就采样；底层成就存储仍由原 achievements 模块管理。
- loop_input.c：鼠标键识别与可见投掷槽选择；FlashlightUseAllowed 由输入与更新共同使用，归入 loop_player.c/player_api.h。

loop_private.h 只声明这些循环模块确需共享的接口与原 game.c 中未有契约的编排状态，没有声明四个私有状态副本，也没有重新引入 game.h。新模块沿用原有契约头，构建清单原本递归枚举 src，无需手写增加链接源文件。

当前 game.c 的源码导航计数为 1628 行，行首 static 声明 0 条。保留了私有封装，只改变所有者；未将每个 helper 都变成公共全局函数。

## 4. 桩分类与新工具

真实状态查询不是常量桩；Collector / Control / Daily / Spider / Scavenger / SoundEvent 的对象字段、计数和计时仍按现有代码读取。对数字常量和空操作已逐项写入带原因的 FIXED_RESULT、PLATFORM_NOOP 或 STUB，详见 [接口分类](常量与空操作接口分类.md)。

明确未实装的条目仍存在，不把加注释写成“功能已经补齐”。特别是 SkillLastResortOneshot 的旧一次性回神钩子、Web 配乐、浏览器 Gamepad API，以及几个可选平台钩子，本轮只显式标明状态。用户可用严格选项让它们继续阻断“无桩”验收。

新增工具：

- `tools/giant_func.py`：默认阈值 200、最多 10 个、硬上限 300，支持 JSON；空源码目录或读取/解析错误返回非零。
- `tools/stub_scan.py`：区分状态表达式、数字/空操作、符号返回，不把返回字符串误判成 void 空实现。标记必须附非空原因，不能用文件级标记豁免后续函数；`--strict-stubs` 对明确未实现条目也返回失败。
- `tools/c_source.py`：共享词法读取器，屏蔽注释/字符串中的假函数和括号，支持同一行多个图鉴查询函数。不代替 C 预处理器或编译器。
- `tools/tests/test_source_tools.py`：已编写源码解析/分类反例，未运行。

既有 source-contract 用例只迁移消费者路径、增加新 loop 源文件，不删除断言，也不拿函数定义位置充当接线成功。
