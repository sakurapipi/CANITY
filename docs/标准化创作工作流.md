# 标准化创作工作流

规则入口：`include/art_direction.h` 的 AD-87～AD-90。
配方入口：`tools/creation_recipes.json`，字段、文件入口、生命周期与交付责任集中登记。

支持怪物、投掷物、成就、局外技能、局内技能、UI六类配方。

```text
python tools/creation_flow.py list
python tools/creation_flow.py new --kind monster --id echo_sentinel --name 回声哨兵
python tools/creation_flow.py context work/creation/echo_sentinel/task.json --max-chars 18000
```

生成的是创作规格和交接文件，不会伪造已经实现的怪物，不会自动修改游戏。
填写task.json中的spec后，先读配方入口；通过symbols按文件挑选真实函数名，再生成有长度预算的context.md。
默认只输出函数索引和必要契约，不反复把大型文件全文交给模型。长度预算是字符预算，不声称等同于token计量。

每类内容都沿同一流程推进：规格 → 权威定义 → 产生/执行 → 状态生命周期 → 文案/表现/输入 → 存档兼容 → 编译交付 → 用户验收。
不可省略上下游挂接来节省token；不可把未执行的验收记为成功。
新ID只追加，保留36×36地图、12容器槽、64世界精灵容量。UI绘制和点击共用几何，关闭模态必须消费输入边沿。
工作流工具不启动游戏、不执行测试、不提交、不推送。
