## 三、两次失败的尝试（已完整回退，无半成品）

### 3.1 技能树（992 行）→ 失败

```
计划：SkillListIndex / SkillTreeCompute / 画布 / 详情 / 拖拽缩放 / 命中测试 整体搬走
实际：连续 3 轮编译失败
  · kSkillList（节点表）、skVX/skVY/skVK、skDrag* 是 ui.c 的 static，两边都在引用
  · SkillTreeDrawContext 结构体、SST_* 宏、SKILL_CROSS_ID 散在文件各处
  · HubZoomButtonRect / HubBackButtonRect 与技能树双向调用
结论：它不是"一簇内聚代码"，而是和 ui.c 深度纠缠。
处置：git checkout 回滚，删除新文件，工作区恢复干净。
```

### 3.2 帧末叠加层（366 行）→ 失败

```
计划：RenderFrameOcclusion / RenderFrameCalibration / DrawPickupToast / DrawSaveStatusBanner
实际：两条提示条共用的 actionErrorMessage / actionErrorUntil 是**多行初始化的 static**，
      按单行切割后 ui.c 残留半截声明 → 出现 'data definition has no type or storage class'
结论：切割工具对多行 static 声明不安全。
处置：同样回滚。
```

**两次都验证了同一件事**：拆文件前必须先把"跨函数共享的静态状态"收敛成结构体或访问器，
否则搬走的是代码、留下的是悬空引用。
