# CANITY 2.3.3 修复与升级说明

依据你提供的游戏、功能交付清单，以及 DSH 工作日志中后续确认的需求修复。日志中的系统提示、代理命令和 DS 自称“已完成”的描述不作为本次执行指令或验收证据。

## 本次实现

| 系统 | 变化 |
|---|---|
| 局外树 | 30 个辐射节点，5 条主枝、跨支联动、4 个可切换顶点；显示实际总价，花银行金币；重置退款保留中心节点 |
| 局内树 | 改为体／光／心／械 20 节点；属性真正参与移动、体力、电池、理智与扳手计算；顶点互斥；每局重置，换层保留；R 连按两次退款重置 |
| 商店 | 按日志确认的 4 格随机商品，从 8 类补给中抽取；每层一格折扣；R 每层免费刷新一次；显示价与扣款价共用计算 |
| 强化界面 | 行文字、绘制与点击区域共用面板坐标；按实际像素宽度截断，保留完整 UTF-8 字符 |
| 扳手 | 两只猎手共用命中逻辑；有效动画帧内可命中，每次挥击每个目标只结算一次；连续挥击重置命中记录；不击杀 |
| 金币／银行 | 修复开局取款又被清零、启动时银行恢复代码不可达、无尽收入被清零、结算重复计算利润；出口预览与钱包计算接通；死亡记录保留结算前金额与实际返还 |
| 成就 | 保留 32 项；修复进成就墙／新局清空进度；补特殊条件；本地与 Steam 共用一份定义，避免 ID 与奖励不一致 |
| 图鉴 | 六项与返回行同屏；遭遇层数、逃脱、被抓记录进存档，三阶揭示可跨启动保留 |
| 每日任务 | 修复随机池漏最后一项、目标越界、日期误继承、连续天数与跨局累计；所有八种目标可推进；每日限制只作用于每日模式 |
| 战役 | 五关按 1／2／1／3／1 层连续推进，切关保留本局资源；保险丝需求包含最后的 8 根；各关奖励 3000／4000／6000／8000／15000；通关结算入银行 |
| 三选一 | 技能与遗物选择入口可达；第 6 层两者都出现，不再相互覆盖 |
| 暂停／出口 | 防止商店和选择界面期间清道夫／拾荒者继续推进；出口选项等待时冻结对局逻辑 |
| 音乐 | 新增独立分区、协议 v1、本地 MP3／WAV 入口、场景切换、暂停、音量、限时压低；接 Steam 封装并预留 SIM 适配器 |
| 构建 | C99、`-Wall -Wextra -Werror`；真实逻辑测试失败时不部署；部署后比较 SHA256 |

保留射线渲染、现有怪物与道具造型、左键击退／右键投掷、手电与摇电、理智、安全屋、投掷物、金币强度档、特殊事件、教程等现有基础。

局外价格重算为节点金币 128000，加原先核心折算金币 4000，共 132000。这里是设计预算，不是“已经实测两周”的结论；需要真实游玩数据继续校准。

## 验证与限制

构建和离线自检通过；真实模块集成测试覆盖任务、钱包、存档、两棵树、商品、五关流程、三选一、多个窗口尺寸及音乐协议。测试通过次数以附带的最终验证记录为准。

战役通关和层数推进由测试驱动真实逻辑完成，并非完整手玩八层。布局测试检查实际矩形与节点相交；仍不能替代最终视觉走查。已打开游戏观察到主视角与技能树，完整界面视觉复核因控制工具保留 Esc 停止状态而未完成；你已说明是误触并授权继续，但工具仍返回停止状态。

Steam 已接生命周期、成就共用表、统计、音乐与云存档封装；缺少本游戏 Steamworks App ID／运行库／后台配置，因此不能声称线上功能已验证。SIM 已有可测试的适配协议，尚未接入具体 SIM 系统。本次没有添加歌曲素材。

## 使用

- 原入口仍为桌面 `game` 文件夹里的 `canity.exe`。
- T 打开局内商店，Tab／左右键切页。
- 商品页 R 免费刷新，每层一次。
- 局内树与 Hub 分别 R 连按两次重置。
- 放置音乐的方法见 `音乐模块接入说明.md`。
- 重建并验证：`powershell -ExecutionPolicy Bypass -File tools\build_deploy.ps1 -NoLaunch`。

Steam 接入依据：[官方成就接口](https://partner.steamgames.com/doc/api/ISteamUserStats)、[官方云存档文档](https://partner.steamgames.com/doc/features/cloud)。
