## 四、超时问题（这次中断的原因）

`extract_function.py` 每搬一个函数要跑 **1~2 次完整构建（每次约 40 秒）**。
一次调用里搬 5 个 = 6~7 分钟，**超过了工具调用超时**。

**下次请这样用：**

```bash
# 一次只搬 1~2 个，或放到后台任务里跑
python tools/extract_function.py <函数名> src/loop_xxx.c <契约头>
```

**注意**：超时中断会留下半成品（函数已从 game.c 删、新文件已写），
**必须先 `git checkout -- include src` 回滚**再继续（这次就是这么恢复的）。

## 五、下一步建议（按性价比排序）

1. **继续用小批量搬**（每次 2 个，避免超时）：game.c 里还有约 60 个 ≤12 行的小函数
2. **每轮跑 `tools/extract_function.py`** 之前先确认 `CANITY_GCC` 是完整路径
3. **大函数**（GenerateLevel 等）需要人工设计模块边界，不建议用工具硬搬
