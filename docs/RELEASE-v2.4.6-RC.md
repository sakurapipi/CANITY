## 1. 删除存档

`PlatDeletePath` 明确区分：0 删除成功，1 原本不存在，负数为平台错误；Windows 保留实际错误码，网页捕获存储错误。
`DeleteSave` 继续尝试所有候选主档、.bak、.tmp，但只有全部完成后才清空运行状态。
任一真实错误保留 g_save.hasRun、hasSave 和 runInProgress，记录首个错误，避免删除失败却报告完成。
新增 `PlatPathExists` 让恢复流程区分本地无文件与本地存在但读取失败，不用删除动作探测文件是否存在。

## 2. 云同步容量与冲突快照

云同步传入本地有效长度与真实 1 MiB 可写容量，容量不再初始化为本地文件长度。
新增 `SteamZoneCloudSyncEx`，把本次真正下载且判定为冲突的云端字节转交存档后端；旧同步入口作为兼容包装保留。
冲突时保留本地主档，实际写出 `.conflict-cloud.bak`。已有副本内容不同则使用带哈希与序号的名称，不直接覆盖旧冲突快照。
云端下载设置 16 MiB 安全上界，过大的对象返回错误，不进行无界内存分配。
旧入口仍可调用；使用新入口取得冲突内存的调用方必须 free，网页空实现保持同样的输出初始化契约。

## 3. 首次云端恢复和回退

仅本地不存在时走首次恢复；本地存在但读失败或截断时保留原文件并报错。
云端恢复校验后检查原子写返回值，不再丢弃失败结果；首选目录不可写时尝试其他存档候选目录。
任何目标已有文件，必须先成功保留 `.pre-cloud.bak` 才允许覆盖该目标；备份失败不直接覆盖本地。
后续同步跟随同一槽最新的候选主档，避免回退恢复成功后仍固定同步旧位置。
多槽处理保留首个错误，后续成功不会掩盖先前失败；冲突和传输错误使用明确错误状态。

## 4. 保存诊断日志

日志依次尝试 CANITY_DATA_DIR、EXE 目录、LOCALAPPDATA/CANITY、APPDATA/CANITY、TEMP/CANITY。
每次写入检查文件大小，达到约 256 KiB 上限后重写；不再只有注释而没有大小限制。
日志头记录实际路径，g_saveLogPath 暴露成功使用的位置；无可写位置时为空。网页改用浏览器日志输出。
日志失败不改写真实存档的状态和错误码。

## 5. 解耦基线

旧文本域/文件基线仍兼容；CI/发布工作流已改为引用 JSON。原预算和旧债上限没有放宽。
