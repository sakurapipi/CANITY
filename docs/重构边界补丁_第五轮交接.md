## 已改的边界

| 层面 | 原问题 | 补丁 |
|---|---|---|
| 射线 → 墙面阶段 | 绘制端重新推导 stepX/stepY，零分量时与投射端的分支约定不同 | WallRay 显式携带投射时的两个步进值；绘制端读取原值 |
| 输入索引 | 公共按键入口与动作查询可能用无效编号、负绑定值访问数组或消耗改绑 | 在处理锁具、改绑、数组之前检查动作与 VK 范围 |
| 输入生命周期 | 失焦/最小化可能保留 keyPressed、拖拽、蓄力、搜索或摇电状态 | 统一清理键位和边沿；结束技能树、改造树和滑块拖拽；取消瞬时操作；仅对实际游玩状态自动暂停 |
| 鼠标捕获 | 捕获丢失只结束滑块，树拖拽仍可能继续 | 捕获丢失统一结束三个拖拽所有者；正常释放捕获不清空整套输入 |
| 新局/离局/继续 | 私有二次呼吸标志和操作状态可能跨会话残留 | StartGame 及公共 ResetRunModeFlags 调用各所有者的清理入口；ContinueRun 原本经该公共入口，因此同时覆盖读档 |
| 冲刺宽限 | “恢复体力后重新准备”的判断嵌在体力耗尽条件下，无法成立；松开冲刺键还会被强制置回冲刺意图 | 将私有标志归入玩家阶段模块，按原超过半体力的阈值重新准备；计时按时间到期；不改写已释放的冲刺意图 |
| 存档 → 世界 | 出口坐标夹取后又被原始值覆盖；非法朝向可进入投影 | 删除重复覆盖；拒绝 NaN、零或异常模长的朝向，有限非单位向量归一化；正常单位向量保留精度 |
| 增量编译 | 仅比较浅层头文件时间，调整编译条件或 `.inc` 后可能复用旧对象；资源只盯 `.rc` | 使用源码/递归头文件/`.inc` 内容摘要、编译参数与工具身份判断缓存；图标、清单等资源同步计入；链接成功后原子记录编译配置 |
| 工具可信度 | 热键扫描静默跳过缺失模块；单行查询容易被误报成常量桩 | 必要源文件缺失立即失败；桩工具增加可查看实际状态返回表达式的信息模式 |

## 归属与兼容

- 鼠标投掷边沿仍由 loop_frame.c 私有维护。取消输入只设置原有 resetInputState 重同步标志，没有为清理方便把私有变量搬成 extern。
- 新增接口声明随实现一起加入 loop_private.h / player_tick.h。game.c 没有增加私有存储，也没有重新使用 game.h 作为跨模块入口。
- 真实状态查询不批量标成 STUB。`--include-queries` 显示诸如 collector.active 的原表达式；它不证明行为已经通过验收。已声明的未实现后端和旧钩子仍在原分类清单中，不以注释冒充功能实现。
- 存档布局、SAVE_VERSION、节点编号和发布版本不变。
- 原桌面 `-Wall -Wextra -Werror` 保留；Web 明确将隐式函数声明、错误指针类型作为编译错误。没有关闭诊断来消除拆分错误。

## 构建缓存的注意点

新增 tools/build_cache.py；工作区内的 work/codex-build/compile-profile.json 只描述已成功编译链接的输入，不是测试或发布验收报告。旧缓存没有该配置，用户第一次构建会完整重编，这是预期行为。此后源码按单文件内容变化重编，头文件、编译配置等变化触发完整重编。构建工具仍按原设计用于单次构建作业，不新增并发构建保障的声明。
