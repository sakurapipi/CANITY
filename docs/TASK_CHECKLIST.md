# 任务清单（开工前过一遍，收工前再过一遍）

> 这份清单不是给人看的流程文档，是**外部义务清单**。
>
> 文献依据：[arXiv 2607.17937](https://arxiv.org/html/2607.17937v2) 实测 ——
> 同一长上下文下，笼统让 agent "自查一遍" 10 次过 5 次；
> 给一份写明义务的清单 10 次过 10 次（p=0.0325）。
>
> 失败不是"做不出来"，是**漏掉几条决定性要求**（覆盖率仍有 0.93+）。
> 所以清单要具体到能打勾，不能写成"注意质量"。

---

## A. 开工前（5 条，全部要能回答）

- [ ] **A1 复现过吗？** 能跑出来问题，或者已经加了探针能量出数字。
      复现不了就先加探针（`tools/` 下写一个），不要直接改代码猜。（AD-86）
- [ ] **A2 这件事现在是几处实现？** grep 关键词确认。
      同一行为若已有两处，先合并再改 —— 否则改一处、另一处继续错。（AD-71）
- [ ] **A3 数值从源码读的吗？** 上限/常量/结构体大小必须来自 `grep`，不能凭记忆。
      反例：电量上限是 `BatteryMax()` 算出来的 150+加成，不是写死的 100。
- [ ] **A4 要改的文件在哪个域？** 读过那张 `docs/modules/<域>.md` 了吗？
      如果横跨三个域，先问自己"能不能只改一个"。
- [ ] **A5 主要特征 ≤ 3 个吗？** 一次只解决一个核心问题，其余记 TODO。（AD-03）

---

## B. 写代码时（6 条）

- [ ] **B1 每个替换都 `assert old in s`。** 不打断言 = 脚本打印"已改"但实际没改。（AD-85 同期教训）
- [ ] **B2 不带魔法数字。** 用 `common.h` 的常量；确实要新常量就加进去并写注释。
- [ ] **B3 新符号进契约头。** 不加裸 `extern` 变量；跨域只走函数。
- [ ] **B4 注释写"为什么"。** 写清是哪次用户反馈、哪个 bug 逼出来的。
- [ ] **B5 C 注释里不出现 `/*` 嵌套**（`-Werror=comment`）。
- [ ] **B6 中文脚本写成 `.py` 文件跑**，不要 `python -c "中文"`（PowerShell 会拆引号）。

---

## C. 收工前（7 条，缺一条不算完）

- [ ] **C1 单文件 `-Werror` 过。**
      `gcc -c <文件> -Iinclude -std=c99 -Wall -Wextra -Werror`
- [ ] **C2 全量 `build_validate.py` 绿。**
      期望 `PASS (12212 checks)` + `partition: OK` + `ALL VALIDATION PASSED`。
      **数字变小就是丢了用例**，要查为什么。
- [ ] **C3 故意改坏一次，确认测试会红。**（AD-65）
      把修复点改回去 → 看到失败信息 → 再改回来。失败信息写进提交说明。
- [ ] **C4 三个指标工具跑过。**
      `module_cost.py`（单域 ≤2500）、`budget_check.py`（中位数 ≤2500）、
      `check_scope.py --allow <域>`（改动不出域）
- [ ] **C5 眼睛看过。** 可见的东西至少出一张图（`CANITY_SHOT` / `sprite_dump` / 截图）。
      只测数据不算数。（AD-66）
- [ ] **C6 提交信息用 `-F 文件`。** 不用 `-m "多行"`（PowerShell 会拆成 pathspec）。（AD-84）
- [ ] **C7 没 push。** 推送由用户下令。（AD-83、用户明确要求）

## D. 常见漏项（历史上真漏过的）

| 漏了什么 | 后果 | 出自 |
|---|---|---|
| 只改一处实现，另一处没改 | "有时候生效" | AD-71 投掷物三条分支 |
| 判据不一致（落地 vs 使用） | 放得下、用不了 | AD-68 相位信标 |
| 改常量没 grep 全部引用 | 只写了一半（技能 15→30） | 作弊工具 / 存档 |
| 测试依赖随机地形 | 换个种子就红 | AD-64 |
| 只测数据不看画面 | 模型"存在"但玩家看不见 | AD-66 |
| 无头环境验手机输入 | hasFocus() 恒真，假绿 | AD-75 |
