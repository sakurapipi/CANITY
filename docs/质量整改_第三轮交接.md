## 一、查询函数不应误标成 STUB

报告把一些单行 `return 表达式` 当成了常量桩，但这与实际源码不符：

| 系统 | 查询读取的来源 | 本轮处理 |
|---|---|---|
| Collector | `collector.active/x/y/bounty` | 保留真实状态查询；补分组注释 |
| Control | `s_type/s_mashLeft/s_timeLeft/s_immune` | 保留控制状态及计时查询；补分组注释 |
| Daily | `s_daily` 的目标、修正、进度、完成与连续天数字段 | 保留挑战生成/加载后的状态查询；补分组注释 |

| Spider | `s_spider` 与 `s_respawnCd` | 保留当前对象及复活计时查询；补分组注释 |

`CollectorSpeedNow` / `ScavengerSpeedNow` 读取共享调参常量，是有意固定的规则，不是假状态。没有为这些有效实现添加错误的“未接线”标签，也没有把动态状态改成常量。本文不宣称重新验证了报告中“71”这个候选集合；其逐项数量不能仅凭单行返回形式确定。

## 二、继续拆分三个大函数

以下行数只用于源码导航，包含注释、空行，不是测试指标；入口变短不表示删除了其内部功能。

| 入口 | 文件 | 本轮前入口行数 | 当前入口行数 |
|---|---|---:|---:|
| `BakeItem` | `src/sprites.c` | 427 | 22 |
| `BakeMonsterHumanoid` | `src/sprites.c` | 411 | 50 |
| `RenderSprites` | `src/render.c` | 360 | 10 |
| `DrawDecoyModel` | `src/render.c` | 73 | 73 |

- **BakeItem**：一次清空画布 → 通用手套 → 光球/石弹/音叉/烟雾/玩偶/胶水变体 → 一次输出。各变体是同文件的私有函数，仅通过本次调用的 `ItemBakeContext` 接收位置/调色板。删除旧代码里重复的第二条 `kind == 0` 分支：它在第一条光球分支之后永远不可达；保留现行光球的绘制。
- **BakeMonsterHumanoid**：局部几何 → 腿 → 骨盆/躯干 → 手臂 → 颈部 → 头 → 专属配件 → 面部。保留原来的两套独立分派：拾荒者/清道夫/守门人配件，与听声/匍匐/长颈/追光/偷电面部。没有让通用面部覆盖守门人的竖排眼；所有阶段仍在原文件内，使用局部 `HumanoidBakeContext`。
- **RenderSprites**：按原插入次序收集场景物、角色/标记、效果/出口 → 原稳定插入排序 → 分派绘制 → 原顺序覆盖层。列表和计数仍归本次栈帧所有，各收集函数保留每项原有容量检查；不改变列表满时优先保留哪些对象，也不改变同距离对象的排序。舱门与家具绘制独立成私有函数；删除家具分支重复且不可达的 break。
- **DrawDecoyModel**：本轮没有重复拆分，它在本地已是上一轮六阶段拆分后的入口。报告仍列 455 行，与当前文件不符；本表显示本轮前后相同的源码行数。

没有通过提升成 extern 来暴露新的绘制状态，也没有改变公共 API、存档格式、资源编号、玩法数值或发布版本。其他超过 200 行的函数仍有继续拆分空间，本轮没有把全仓大函数清理记为全部完成。
