# CANITY 审美规范优化记录

2026-11-02。已直接更新游戏源码的 `include/art_direction.h`，并同步修正 `include/art.h`、`src/art.c`、`include/ui_theme.h` 的过时说明。

## 组织方式

保留原有 1—24 编号，新增 25—32，共 32 条。按造型光照、UI 与状态、数据与模块、验证交付建立索引。规则写成执行方法和验收依据，历史事故压缩为能解释规则的例子。

## 修正的旧规则

| 旧问题 | 现在的规则 |
|---|---|
| 守门人横排眼／旧桶状造型与后来认可的 v3 冲突 | 以 v3 的尖顶、收腰、竖眼及独立追逐变体为当前基准 |
| 所有绘制必须晚于最后一个遮罩 | 根据目标层级与实际执行路径判断；需要显示的缓冲写入发生在提交前 |
| 行号可单独证明图层正确 | 行号只帮助定位，分支、调用链、缓冲和实际画面共同验证 |
| 中央永远只能有遮罩 | 模态任务优先；QTE、出口选择可占中央，其他信息明确避让 |
| 恐怖不能有一对眼、必须恰好三个特征 | 保留已认可基准，主要特征为 1—3 个，不强行为形式改模型 |
| 整个最终画面只能有四五个颜色 | 约四五档用于主体明暗起步，按材质与实际呈现验收 |
| 导出精灵是唯一有效验证、禁止所有绿色像素 | 导出与实机场景互补；按具体变体检查不应出现的颜色 |
| UI 已经全部统一颜色、对比度直接写 4.8:1 | 如实记录历史色值尚未迁移；对比度实测后再标数值 |
| 一个概念只能有一个变量 | 保留银行／携带等不同状态，计算和变化走同一权威入口 |
| 只能用某一种文本替换工具编辑 | 备份并确认修改边界，避免覆盖已有未提交工作 |
| bench 重做前的文案暂缓豁免仍然存在 | 删除过时豁免，新数值文案取真实来源或有一致性验证 |
| 末尾规则在头文件保护范围外 | 全部规则与兼容调色常量放回同一个保护范围 |
