## 一、项目背景（实现方必读）

**CANITY** 是一个 **C99 + Win32 GDI 软件光线投射**第一人称恐怖逃生游戏，Windows 桌面 + Web(WASM) 双端。

**代码规模**：约 101 个 `.c`，5.5 万行；主文件 `src/game.c` 已拆到约 1,600 行（装配 + 调度）。

**构建与验证**（必须全绿才算完成）：

```
python tools/build_validate.py     # 编译 + 14,500+ 条断言 + 存档夹具 5/5
python tools/partition_check.py    # 五条分区规则 S1~S5
python tools/content_check.py      # 内容一致性 21 条
python tools/build_web.py          # Web 端回归
```

**分区规则（不可违反）**：

```
S1  系统头只允许出现在 include/common.h
S2  存档读写只能经 src/save/
S3  分区符号各归各家（不得跨分区定义）
S4  内容中枢（content_db）不许反向依赖系统模块
S5  include/game.h 只允许 game.c 引用
```

**存档**：`SAVE_VERSION 39`，格式**只允许末尾追加**；任何字段语义变化都必须带老档迁移逻辑 + 5 个存档夹具全部通过。

**发布纪律**：只做本地提交，**不许推送**。

**代码风格**：注释用中文，写清「为什么改」而不是「改了什么」；不要留 TODO 占位。

# A. 表现层

### A1　整体恐怖感提升
游戏内界面（HUD、边框、提示、转场）整体增加压迫感。要求至少 3 处可见改动（示例方向：暗角加强、扫描线/噪点、偶发闪烁、血色点缀、字体轻微抖动）。

### A2　理智驱动画风递变
把 SANITY（0~100）映射为一条「恐怖强度 t∈[0,1]」，随 t 升高逐级加重视觉干扰（色偏、暗角、噪点、抖动、边缘扭曲等），**低理智的观感应明显比满理智更难看清**。

- 验收：SANITY 100 / 50 / 20 三档截图应有明显差异。

### A3　主题音乐扩充
新增多首配乐，按情境切换（菜单 / 局内探索 / 追逐 / 安全屋）。至少 3 首新曲，能正确跟随情境切换。

> 注意：C1 的音游需要用「主题曲」做节奏采集，所以主题曲必须**有明确节拍**、可分析。

### A4　金币配色修正
所有表示「金币/黄金」的数值，颜色改为**金色系**（暖金），不要沿用主题蓝。范围：主菜单、局内 HUD、商店、银行/结算界面。

### A5　主题房间重做
现有 7 种房间主题表现雷同，重做使其在材质、色温、陈设、光照上**一眼可区分**。

- 【待设计】7 种主题各自的视觉语言由实现方设计。

# B. 界面

### B1　主菜单重做
- 重排布局；去掉孤立装饰元素与不一致的分隔线；版本号不贴边；
- **取消「最高层」显示**；
- 菜单项数量收敛，避免再加一项就溢出。

### B2　帮助系统重做
现状问题：帮助内容**严重过时**，新手想查「某个技能怎么用」时查不到，等于无用。

要求：
- 按当前版本重写内容；
- 必须覆盖：基础操作、核心循环、**全部技能说明**、怪物应对、经济系统；
- 支持按分类浏览，最好能按技能名定位。

- 验收：随机抽 5 个技能，都能在帮助里查到效果说明。

### B3　训练营改为两层
- **第一层**：`进入菜单 → 训练营`，即**原有训练营，不做改动**。
- **第二层**：局内按 **B 键**进入，**尚未设计，需要重新设计**。

第二层的设计要求：
- 以**新手引导**为主要目的（不是自由练习）；
- **不做迷宫结构**，要**线性引导**：一步步教操作（移动 → 手电 → 搜查 → 投掷 → 躲藏 → 逃脱），每步有明确提示与完成条件；
- 引导节奏要短，能让新手在几分钟内过一遍。

- 【待设计】第二层的具体教学步骤、触发条件、提示文案、完成判定，全部由实现方设计。

### B4　进入训练营道具无限
- 第一层（原训练营）正常进入时，**道具/投掷物无限**，不消耗。
- 第二层同理。

# C. 玩法

### C1　校准小游戏重做为**音游**（本批次工作量最大）

**形态**
- 按 **空格** 开始；
- **QWER 四条校准线**（每键一条独立线）；
- 屏幕**左侧一个小方框**，框内为音游区域；
- 音符**从上往下掉落**（类似《钢琴块 2》），落到判定线时按对应键判定。

**音乐与谱面**
- 使用游戏**当前主题曲**；
- **截取音乐中间的一个片段**作为谱面时长（不要用全曲）；
- 对截取片段做**节奏采集**，生成谱面（离线分析 → 谱面数据随包发布）。

**难度**
- **层数越高，难度越大**（音符密度 / 下落速度 / 判定窗口，具体由实现方定）。

**失误与惩罚**
- 累计**弹错 5 次** → 立即判负、结束本次小游戏（不结算奖励）；
- 判负后 **30 秒内不得再次进入**。

**奖励（连击）**
| 连击 | 奖励 |
|---|---|
| 2 连 | +2 理智 |
| 3 连（及以上） | +3 理智 |
| 上限 | 单次小游戏最多回复 **10 点理智** |

- 连续按**两下空格**退出小游戏。

**接入方式**
- 音游通过**调用现有的校准入口函数**接入（具体是哪个函数由实现方在代码中确认并复用，不要另起一套并行逻辑）。

- 【待设计】判定窗口、连击断连规则、音符生成算法、谱面数据格式，由实现方设计。

### C2　取消「投石」技能，替换为新技能
- **现状**：投石技能**没有动画**，且占用热键 **G**。
- **要求**：
  1. **取消投石技能**；
  2. 替换为一个**新技能**：`【待设计】由实现方设计`（需符合游戏调性：潜行/逃生/资源/信息类，避免再做一个"无动画投掷"）；
  3. **释放热键 G**，交给新技能使用；
  4. 新技能必须有**明确的视觉反馈**（不许再出现"没动画"的技能）。

- 设计交付物：技能名（中英）、效果、数值、解锁位置（技能树）、G 键行为、视觉反馈方案。

### C3　修整服务改为**按百分比付费 + CD**
**付费规则（关键）**
价格与**当前理智**挂钩，**理智越低越贵**。用户给的示例仅用于说明方向：

```
理智 30  → 需 60 金币
理智 50  → 需 30 金币
（示例，非最终数值）
```

- 实现要求：价格 = 由「当前理智 / 缺失理智」推导的**百分比曲线**，不允许写死固定价；
- **具体曲线与系数由实现方设计**（要保证低理智时"修得起但不划算"）；
- 必须有一个**价格预览**（玩家在按下去之前能看到要花多少）。

**CD**
- 同一修整服务加**冷却限制**，CD 内再次使用应被拒绝并提示剩余秒数。
- 【待设计】CD 时长、是否分层数变化，由实现方设计。

### C4　补给商店加**刷新键**
- 新增刷新键（键位由实现方选，避免与现有按键冲突）；
- **刷新冷却 60 秒**；
- CD 内按下要给出明确提示（剩余秒数）。

### C5　技能树扩展 + 结构重画
**结构**
- 现在有 3 条分支：**北 / 西南 / 东南**；
- 需要**画出一条主干线**把三条分支串起来；
- 三条分支上的节点 = **流派技能**；
- 主干线旁有**三片空白区域**，用于放**通用技能**与**弱关联技能**；
- 三片区域要有**颜色区分**与各自特点。

**扩展**
- 技能树要**向外扩展**（容量变大）。
- 【待设计】总节点数、三片区域各放多少、扩展后的排布与美术方案，**由实现方设计**。

**可读性（附带修复）**
- 当前节点短名只有 1 个字（界面上全是「静/轻/夜」），几乎认不出来 → 改成 **2~3 字**，或提供悬浮显示全名。

# D. 怪物系统

### D1　三只听声鬼的数值与分工（按此表落实）

| 序号 | 听力 | 特殊能力 | 速度 |
|---|---|---|---|
| 第 1 只 | **100%** | 无 | 基准 |
| 第 2 只 | **75%** | **减速技能**（对玩家施加减速） | 基准 |
| 第 3 只 | **50%** | 无 | **最快** |

**已知障碍**：当前常量下第 3 只"最快"做不到 ——
`MONSTER_SPEED_BASE 1.90`、上限 `2.10`、倍率 `1.30` → 被夹到 2.10，相对基准最多快 10.5%。
实现方需要**重新设定速度/上限**，使「第 3 只明显更快」在数值上成立，同时**不破坏「玩家永远跑得掉」**这条设计底线。

### D2　入场时间写成函数
新增一个函数（如 `HunterSpawnDelay(level)`）控制三只的入场节奏：
**层数越高，出场越快**。不要散落的魔法数字。

### D3　第一层强度削弱
第 1 层当前难度过高，需要削弱（怪物强度 / 数量 / 出现率）。

### D4　怪物出场规则重设计
- 削减各怪**出场频率**；
- 为每种怪设定**最低出场层数**（例如：某些怪第 1 层不该出现）；
- 输出一张「怪物 × 层数」的出现表，作为实现依据。

### D5　追光鬼重做：**没有听觉，只被光吸引**
- 追光鬼**不靠声音**（现状"没有声音"这点不对，应为：它压根不听声音）；
- 它**看到光源**（手电、信号弹、发光道具）就会冲过去 —— 这才是它吓人的地方；
- 玩家关灯的代价与收益要因此成立（关灯避开它，但看不见路）。

### D6　追光鬼**双只互卡** Bug（缺陷）
场上有**两只追光鬼**时会互相卡住，其中一只完全不动。
要求：修复互相占位死锁（分离力 / 避让 / 目标抢占 / 状态机任一环节）。

### D7　蜘蛛怪加入图鉴
- 游戏内**应有蜘蛛怪**，其代码是后期添加的 —— **先确认代码是否存在**；
- **图鉴第 3 条「旧版记录」替换为蜘蛛怪**；
- 附带修正：图鉴标题写「现行 2 / 6」，但列表实际有 7 条，**计数与实际不一致**，一并修掉（计数应按真实数量动态计算）。

### D8　偷钱怪 / 宝箱怪出场率过低
提高两者的出场权重，使其在合理层数能稳定遇到（与 D4 的出场表一起设计）。
